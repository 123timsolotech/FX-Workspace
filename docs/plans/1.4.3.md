## Part 1 - The thinking mark: Orbs

Today: `.think` is five empty `<i>` elements, and each appearance restyles them with CSS keyframes (about 150 rules).
A change of action fades the old animation out (140 ms) and springs the new one in. That's a cut, not a transition:
the dots can't travel from one shape to the next.

### 1.1 How it moves
- **Three orbs** (a core and two satellites; four in the bigger spots) drawn by one small motion engine:
  - Each action is a *formation*: a function of time that gives every orb a position, size and glow.
  - A change of action blends the old formation into the new one over ~450 ms, with easing. The orbs fly from
    where they are into the new pattern, mid-motion, with no restart and no fade. A change that arrives mid-blend
    starts from the current blended positions, so quick changes never jump.
- **The seven formations:**

  | Action | Formation |
  |---|---|
  | think | satellites orbit the core lazily on tilted, different-sized orbits; the core breathes |
  | read | the orbs line up and sweep left-to-right like eyes along a line, then return |
  | search | one satellite swings wide like a radar sweep; the other pulses at the core |
  | tool | the orbs snap to a triangle and rotate in crisp 120° steps, like gears clicking |
  | write | the orbs trail one after another along a flowing wave, like a pen's tip |
  | draw | the orbs swirl and blend colours (the appearance's palette) |
  | wait | everything slows to a gentle bob, dimmer; nothing orbits |

- **One engine for every mark on screen:**
  - a single `requestAnimationFrame` loop; it sleeps when no mark is visible, when the window is hidden in the tray,
    and when the tab is in the background (0% CPU then);
  - each frame writes only `transform`s and `opacity`, so it stays on the GPU compositor with no layout work;
  - Motion off and "reduce motion" show a still formation per action, which still changes shape when the action
    changes.
- **The same mark in every spot:** the Thinking row, the action line, the web-search row, Research's bar, the mini
  window's chat strip and the sidebar's running dot. When the Thinking row hands over to the action line, the mark
  carries on: it doesn't restart.

### 1.2 One version per appearance
The engine moves the orbs, and each appearance only *dresses* them (colour, shape, glow, timing), so all
9 appearances × 7 actions come from one set of formations.

| Appearance | Orbs look like |
|---|---|
| Classic | Light: ink dots. Dark: warm accent planets with a faint ring on the core (a nod to the Saturn mark) |
| Sunrise | soft suns with a corona glow; dusk turns them apricot |
| Terminal | square pixels that move on a grid, stepping instead of gliding (stepped easing) |
| Eclipse | a dark disc passing over a bright corona; satellites cast the eclipse |
| Aurora | blurred glowing orbs that leave a short light trail |
| Claude | clay-coloured orbs; *think* curls them into a ✻-like rosette |
| ChatGPT | one solid dot at rest; satellites appear only for actions, then fold back into it |
| Grok | hairline rings instead of filled orbs; quick, sharp easing |
| Gemini | gradient-filled orbs (blue to rose) with a sparkle at the core |

### 1.3 Legacy and the setting
- **Settings › Appearance › Thinking mark:** Orbs / Legacy, plus a live preview that cycles through the seven
  actions.
- **Legacy keeps today's marks unchanged** (the existing CSS) and its 140 ms swap.

## Part 2 - Finish the four AI-inspired appearances and drop their Beta tag

Today the Claude, ChatGPT, Grok and Gemini appearances have 37-45 style rules each. The finished ones have 59-149. Where
an appearance has no rule, a part of the app falls back to Classic, and that's the "some details are off".

### 2.1 Audit harness (built first, reused for every appearance)
- **A script that drives the app in the browser pane** and takes a screenshot of every surface in every appearance and
  scheme:
  - sidebar, Home, chat with a long reply (code, table, list, quote), the composer and its tool pills;
  - the context breakdown, approval cards, menus, toasts, dialogs and the command palette;
  - Settings (all 7 pages);
  - Images, Videos, Music, Notes, Docs, Mail, Compare, Projects and Routines;
  - Labs, the mini window, and phone width.
- **Automatic checks per appearance:**
  - **Text contrast:** every text colour against its background at WCAG AA (4.5:1, or 3:1 for large text).
  - **Focus rings:** visible on every focusable control.
  - **Classic leaking through:** any colour on screen that isn't one of the appearance's own tokens is flagged.
  - **Layout:** no horizontal scroll, and no clipped text, at 360 px and 1920 px.
- The output is a contact sheet (an HTML page of the screenshots, one row per surface) for review.

### 2.2 Per appearance
For each of Claude, ChatGPT, Grok and Gemini, light and dark:
- **Fill every gap the harness shows.** Each fix goes into the appearance's tokens first, and gets its own rule only
  where a token can't do it.
- **Signature details, matched to what each is inspired by** (no logos, names or assets of theirs, as today):
  - **Claude:** serif replies, the clay accent, the thinking words; quiet rounded cards.
  - **ChatGPT:** the pill message box, the plain sidebar, the blue-to-purple slider; generous whitespace.
  - **Grok:** pure black or white, hairlines, sharp type, square-ish controls.
  - **Gemini:** blue-grey surfaces, the gradient accent, "Show thinking"; soft large radii.
- **Check them with each of the 4 layouts** (Studio, Focus, Operator, Command).

### 2.3 Re-check the 1.4.2 appearance-switch fix
Switch between all 18 appearance/scheme pairs in a scripted loop (every pair to every other), and check that nothing
from the old one is left: no stray tokens, classes or selected card.

### Done when
- [ ] The contact sheet has no flagged item for any of the 4 appearances.
- [ ] You've looked at the contact sheet and agreed. Then the Beta tag goes from Appearance, the palette and
      the docs.
- [ ] Switching between all 18 appearance/scheme pairs leaves nothing behind.

## Part 5 - Proposals (you pick)

The app already does a lot, so here are three additions that make what exists easier to use, and three merges that
make it smaller.

### Additions
- **A. First-run welcome** (3 short steps, skippable, never shown again):
  - pick a starter model that fits this GPU (one click; Find models already knows what fits);
  - pick an appearance;
  - see the privacy summary: what stays on the PC and what goes out.

  Today a new user lands in an empty chat with no model loaded.
- **B. "What changed" after an update.** After Update now, the first start shows the release notes for that version
  once, from the notes already shipped in `docs/releases`.
- **C. Settings search shows where things are.** Search already finds settings. This makes a result jump to the
  setting and highlight it for a moment, instead of only opening its page.

### Merges and cuts
- **D. One "Connections" page** for Connectors, MCP servers and Channels: three lists of things that link the app to
  the outside world, in one place, with one status line each. Settings tabs go from 18 to 16.
- **E. Network and Web search on one page.** Both are about how traffic leaves the PC (proxy, Tor, VPN, private
  search modes); split across two pages, people miss half of it.
- **F. Remove what nobody can reach or that duplicates something:**
  - list unused code paths, settings with no effect, and CSS for removed views;
  - delete them, with a size report before and after (index.html is 20,141 lines today).

  Nothing visible is removed without your yes.
