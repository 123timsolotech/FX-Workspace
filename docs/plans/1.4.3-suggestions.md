# 1.4.3 - suggestions for later (need your OK)

Found while building 1.4.3, outside the agreed plan, so not built. Each entry says where it came from and why it
matters.

## Fixed along the way (small, and they blocked the planned checks - tell me if you'd rather I hadn't)
- **The server stopped itself under a running app.** It checks once a second that the desktop app is still there;
  a single failed check (while the PC loaded a 9.7 GB model for the MoE test) read as "closed", and the window was
  left with no server behind it. launcher.pyw now stops only after three checks in a row find the app gone, and a
  check that can't tell counts as "still there". Tested.
- **The NCM story writer couldn't write** with HazyResearch's current code (the setup downloads their latest):
  their TinyStories config no longer lets the model write the first level, and generate() asserted. The worker now
  draws it from the checkpoint like their own eval script. Checked live: a full story in 2.9 s.
- **"Types or clicks" pill** on approval cards was the size of a text box (its class name is also the text box's).
- **Icons and times glued to their labels** in Images, Videos and Music's switches ("☆Favourites", "Fast~13 s").
- **The Videos progress bar** (the 2026-10-13 report) turned out to be done already - stages, real step and tile
  speed, decoder retries. Nothing to do; the old note is removed.

## Found in the live checks
- **DeepSeek-Coder-V2 can't load on this PC with its saved settings:** its context needs a 4.6 GB KV cache, which
  doesn't fit beside its weights in 8 GB of VRAM ("failed to allocate buffer for kv cache"). Lowering its context in
  Settings › Models fixes it (Diagnostics can pick a size that fits).
- **The MoE cache test shows llama-server's raw error** ("500 Server Error ... /v1/chat/completions") when the model
  can't load. It should say "DeepSeek-Coder-V2 couldn't load - not enough GPU memory for its context; lower it in
  Settings › Models" (the reason is in llama-server.log).

## Ideas for later
- **The desktop app could restart a server that stopped** (or say so in the window). After the stop above, the
  window stayed open with nothing behind it until the app was restarted by hand.
- **Settings › Appearance is long.** Thinking mark, Notifications, Motion and the window options could fold into
  "More" groups the way Layout already does.
- **The welcome's model step could offer a vision model** too (Gemma or Qwen VL), for screenshots.
- **The appearance audit (tools/appearance_audit.js) could run before every release** - about 10 minutes for
  486 screens; it needs `npm i playwright-core` once.
