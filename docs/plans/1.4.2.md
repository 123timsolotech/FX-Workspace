# Plan: FX Workspace 1.4.2

Written 2026-10-27, from the features picked out of the Pithagoras video (Codacus), the llama.cpp MoE-cache video and the NCM research (HazyResearch). Built in phases; **each phase stops for review** before the next. Each phase ends with:
- the full test suite;
- a live check on this PC: real replies timed against the model's first-token time, as for 1.4.1;
- an installer build only after the last phase.

**Already done for 1.4.2 (uncommitted, 1,411 tests pass):** prompt-injection defences. The model no longer reads text hidden on web pages. An address a page could have built asks before it opens, and one carrying your key is refused. The detector reads through disguised letters.

**Also done for 1.4.2:**
- **Switching appearances no longer leaves the old one behind.** The new choice was only recorded inside the switch animation, a frame or up to 250 ms later. Anything redrawn right after a switch used the old appearance: its card stayed selected, and parts of its look stayed. Reproduced (Terminal → Classic kept Terminal selected) and fixed; the light/dark toggle had the same bug.
- **Political and controversial questions are no longer refused as "outside this app's limits".** The chat-limits check is a small model call. It misfiled them, although no category covers opinions; its instructions now allow politics, religion and controversial views explicitly.
- **A red "Relaxed limits — for uncensored (abliterated) models" switch** sits at the top of Settings › Privacy. Searching "uncensored", "abliterated", "limits" or "refused" in Settings finds it. It turns every optional check off in one go, so the model answers everything itself. Sexual content involving minors stays refused.

The guiding idea from the video: on a local model, **context and inference are the budget**. Every feature below must show what it costs, run nothing unasked, and stay off until it earns its place.

## Phase 1 - See and control what the model spends

Small, independent, and they make the later phases measurable.

1. **Token breakdown.** The context meter opens a breakdown of the next request:
   - system prompt;
   - persona and identity files;
   - memory;
   - each tool group and each MCP server's tools;
   - skills, history and the room kept for the reply.

   Counted by the loaded model's own tokenizer (llama-server `/tokenize`), so the numbers are real, not estimates. A fresh chat's fixed cost was ~6.8K tokens on a 16K model today; the target is to make every part of that visible.
2. **Tools off per chat.** Pills under the message box, like Pithagoras's, turn tool groups and individual MCP servers off for this chat. They're saved with the chat. The breakdown shows the saving immediately.
3. **Chat status dots** in the sidebar: running, waiting for your approval, error, or **interrupted** (the app closed mid-reply). The crash-safety record already exists (`sessions.mark_pending`). An interrupted chat says so and offers "Continue".
4. **Background monitor.** A Settings › This PC panel lists every model call that isn't part of a reply you asked for:
   - warm-up loads, chat titles, Compare, routines;
   - proactive help, with what triggered each.

   Each line shows tokens and time. A switch can block all background model use. A one-time audit confirms nothing calls the model unasked; Hermes's "decoding with nobody asking" is exactly what we don't want.

## Phase 2 - Keeps working when the window is closed

1. **Close to tray.** Closing the window hides it; the server, a running reply, routines and llama-server keep going. Quitting is in the tray menu, and an "Ask me the first time" note explains it once. A setting switches back to "closing quits".
2. **Done notifications.** A Windows notification when a long task finishes or needs your approval, with a click that opens that chat.
3. **Optional: start with Windows, hidden in the tray.** The setting exists; it gains "start hidden".
4. **The mini window, built in (replaces the Edge overlay).**
   - **Today:** "Always on top of Roblox Studio" opens the `?hud=1` panels in a separate **Edge** app window (`app_window.py`), using Windows calls for see-through and click-through. It looks and behaves like a different program.
   - **Rebuilt inside the desktop app:** a second Electron window with no frame, the app's own theme and its live chat, plus:
     - see-through and click-through as real window options;
     - snapping to a screen corner, or following Roblox Studio (the server already finds Studio's window);
     - a pin/unpin button and the same Stop button.
   - **Open it from anywhere:** the top bar, the tray menu or Ctrl+Alt+M, not only with Roblox.
   - **The assistant can control it:** a new `mini_window` tool opens, closes, moves, resizes and sets the opacity when you ask ("put yourself in the corner while I play"). It runs without asking: it only changes the app's own window.
   - Edge is then no longer needed for anything; the Edge code path is removed.
5. **Memory for the GPU:** while the window is hidden and idle, the model unloads after a set time (an existing idea, now with a setting), so a game isn't fighting the AI for VRAM.

## Phase 3 - Use it from your phone

Off by default, and switched on in Settings › Remote access.

1. **Your network only.** The server also listens on your home network, or only on your Tailscale address (recommended, since it's encrypted). Never the open internet: the setting refuses public addresses.
2. **A password, required.** It's stored as a strong hash, with a sign-in page, a session cookie, a lock-out after repeated wrong tries, and a list of signed-in devices that you can sign out.
3. **A QR code** for the address, plus "Add to home screen": the page becomes an installable app (PWA) with a phone layout check.
4. **What a phone may do.**
   - **Allowed:** chat, approve or refuse actions, notes and tasks, read results.
   - **Not from a phone, unless you allow it:** screen and mouse control, changing security settings, and API keys.

   The approval cards work on the phone, so you can say yes to a step from the balcony.

## Phase 4 - Channels: Discord, Slack and a webhook

You picked these three; Telegram can be added later the same way.

1. **One channel framework.** Each channel is a plugin, like Pithagoras's. A message from **you** (an allow-listed account) starts a turn in that channel's own Assistant session, and the reply goes back to the channel. Anyone else is ignored and logged.
2. **Never block the listener.** A turn runs in the background, while the channel keeps listening for your next message, an approval or "stop". This is the deadlock from the video, designed out from the start.
3. **Approvals in the channel:**
   - Discord: buttons.
   - Slack: interactive buttons, using Socket Mode, so no public URL is needed.
   - Webhook: a reply link with a one-time code.

   Sending a message on your behalf still always asks.
4. **Webhook.** A local address with a secret, for Home Assistant, n8n, iOS Shortcuts and the like, over the home network or Tailscale only.
5. **The webhook ships first,** being simplest and testable without accounts. Discord and Slack need a bot token from you.

## Phase 5 - Who it is, what it remembers, and two kinds of session

1. **Identity files with explaining headers.**
   - **Soul:** who the assistant is.
   - **About me:** you.
   - **Memory.**

   They're editable in Settings, as plain markdown. Each is sent with a header that tells the model what the file *is*, for example "This file defines YOU, the assistant. Speak and act as described." In the video, a model read its soul file as notes about someone else and called itself "made by Baidu"; the header is what fixed it. Personas build on top.

   **Test:** ask "who are you" and "what do you know about me" on the 4B and E2B models before and after.
2. **Linked memory graph.**
   - **Storage:** memory becomes plain markdown notes (`data/memory/*.md`, OKF-style front matter) linked to each other.
   - **Write-time rules:** a new fact updates the note it belongs to instead of adding a duplicate, and a contradiction replaces the old value.
   - **Start of each session:** a compact overview (topics and one line each) goes in, never the whole memory.
   - **Upkeep and viewing:** a maintenance pass fixes orphaned notes and broken links, and a graph view lives in Settings › Memory.
   - **Moving over:** today's `memory.json` entries move over automatically, and the old file is kept.
   - **Alternative:** connect Codacus's Understory through MCP instead. Both can't be on at once.
3. **Work and Assistant sessions.**
   - **Work:** a project folder with its own instructions file, and file, code and command tools. No routines, channels or memory writes unless asked.
   - **Assistant:** the default chat, channels and routines. Errands, memory, notes, mail; no project tools.

   Each kind only carries the tools it needs, so neither crowds the other's context. Today's projects become Work sessions.

## Phase 6 - Sandboxed runs for risky tasks

1. **Sandbox folder mode.** A chat can be switched to "sandboxed". File tools then only reach a scratch folder, and commands run as a restricted Windows process (a job object with a low-integrity token, no access to your folders, a memory and CPU cap). Opening addresses follows the new injection rules. Results can be copied out with one approval.
2. **Windows Sandbox for unknown programs.** Windows 10 Pro includes Windows Sandbox: a throwaway virtual PC, wiped when it closes. "Run this download or script in the sandbox" opens it with only that file shared. It needs the Windows feature switched on once, which requires admin, so setup explains it.
3. **Not in scope:** Docker containers, since Windows Sandbox is already on this PC.

## Phase 7 - Speed and Labs

1. **MoE expert cache with a speed test.**
   - **Who it's for:** your build (11541) supports `--moe-cache-mib`, and three models use it: Qwen3.5-35B-A3B, Ornith-1.5-35B-A3B, and one more with `n-cpu-moe`.
   - **The catch:** the video measured *slower* decoding on 8-12 GB cards when the cache misses often.
   - **How it's tested:**
     - Settings › Models › "Test the MoE cache" runs the same prompt three times each without the cache, then with 2-3 cache sizes that fit in free VRAM.
     - It measures prompt and writing speed separately.
     - It keeps a size only if writing is **at least 5% faster** and prompt speed doesn't drop. Otherwise it changes nothing.
     - About 15 minutes per model; results are kept and shown.
2. **NCM story writer (Labs, Beta).**
   - **What it is:** a Labs page under "Research models". It downloads HazyResearch's TinyStories NCM (578 MB) to **E:** (G: has 0.2 GB free), and you give it a story start.
   - **The reveal:** it writes the story **level by level** — a rough outline, then sharper, then the full text — with each level shown as it lands.
   - **Speed comparison** on the same task:
     - a small word-by-word model (Labs' tiny GPT trained on TinyStories, about 10 minutes of training);
     - your local chat model.

     It shows stories per second and time to the full text.
   - **Labs engine:** runs in the existing Labs Python, after a dependency check.
   - **Not possible yet:** training your own NCM. The repo publishes no training code.

## Order, size and decisions

**Order:** Phase 1 → 2 → 3 → 4 → 5 → 6 → 7. Phases 1 and 7 are independent and could swap if you want the speed test sooner.

**Size:** this is a big release, closer to a 1.5.0 than a patch. Phases 2-4 change how the app runs and who can reach it. Calling it **1.5.0** would tell users more is new. Your call: 1.4.2 as you said, or 1.5.0.

**Decisions before the phases that need them:**
1. *(Phase 2)* Closing the window: hide to tray by default, or keep "closing quits" as the default with tray as an option?
2. *(Phase 3)* Remote access over Tailscale only (recommended), or Tailscale and the home network?
3. *(Phase 4)* Which channel first after the webhook: Discord or Slack?
4. *(Phase 5)* Memory: our own linked notes (recommended), or Understory through MCP?
5. *(Phase 6)* Set up Windows Sandbox (one admin step), or only the sandbox-folder mode?
6. *(Phase 7)* NCM files on E: (recommended) or A:?
