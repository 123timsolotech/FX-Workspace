# FX Workspace 1.4.4 - plan (draft for review)

Two parts: **Tor built in** (privacy, with no setup beyond the installer) and **Deep search** (searching that goes
further into sites, in the spirit of Grok's DeepSearch). Nothing is built until this plan is approved.

## Stage 1 - fixes found in use (done first)

From your report on 1.4.3 (screenshots of a Research turn, the Working state):

1. **Qwen 3.5 4B "randomly" loaded Gemma 4 Vision.** Cause (from the logs): the chat had an image in an earlier
   turn, so *every* later message counted as "has a screenshot" and swapped to the vision model; the load-ahead
   while you type then swapped back - two reloads per message. Fix: only an image in *this* turn swaps to a vision
   model; earlier images go to a text model as a short note ("attach it again to have a vision model look"), and
   along at no cost when a vision model is already loaded.
2. **Say clearly when a model is loading.** A reply that waits behind the load-ahead now says "Loading Qwen 3.5 4B
   into memory · 12s" instead of a thinking phrase (the load holds a marker the waiting reply reads).
3. **Research took "retry" as the question to research.** retry / try again / redo / keep going now pick up the
   last stopped or failed research, like "resume"; with nothing to pick up it says so instead of researching the word.
4. **Research's bar sat half way with "0 of ~18 sources".** The bar now moves with questions finished and sources
   read, with only a small step for the stage inside a question.
5. **"Reading 6 pages… R M E D V".** Sites whose icon doesn't load showed their letter on a tile the colour of the
   page - loose letters. They now get a tile in a colour of their own.
6. **Animations with no purpose.** Every thinking mark moves slowly and steadily (about 3-4 s a turn), with no
   clicking steps, no colour cycling; reading and writing in the Claude look are the same turning nodes as
   thinking; a new kind of work shows only once it has lasted 0.6 s (a tool call between two thoughts no longer
   sets the mark morphing back and forth); changes glide over 0.9 s. The thinking words stay put for the stretch
   instead of a new phrase every 2.5 s; the Claude look still updates to the newest line of reasoning.

7. **Data and files** (asked for during part A): Settings › Data and files lists everything the app keeps on this PC
   (chats, deleted chats, images, videos, music, attached files, research notes, run history, lookups, logs, update
   backups, the assistant's browser, voice; memory and the window cache open-only), with sizes, **Open** in File
   Explorer for each and the whole data folder, and **Clear** - to the Recycle Bin by default or for good, chats
   optionally keeping the pinned ones, never outside data\, never while a reply runs, never from the phone.

## What exists today (1.4.3)

- `netlayer.py` already routes every outbound request: app-wide route (direct / system / proxy / tor) with per-part
  overrides (search / models / other), a kill switch, Require VPN, socks5h so DNS goes through the proxy, and a
  socket guard. Its "tor" route only *finds* a Tor someone else runs (Tor Browser on 9150, Expert Bundle on 9050).
- `search_engine.py`: providers Brave/Tavily (keys), SearXNG, DuckDuckGo HTML (no key), DDG Instant Answer.
- `agent/research.py`: Research - plan card you approve, rounds of 2-3 searches + parallel page reads, notes ledger,
  Quick ~8 to Ultra 300-400 sources, a written report.
- What's missing: Tor needs a separate install; a normal reply's search reads only a few top results and never
  follows links inside a site; there's nothing between "one quick search" and "a full Research report".

## Part A - Tor, built in

### A1. Ship Tor in the installer
- `installer/build.ps1` downloads the **Tor Expert Bundle** for Windows x86_64 (stable; today 15.0.26 / tor
  0.4.9.14, 21.5 MB `.tar.gz`) from dist.torproject.org, checks its **GPG signature** against the Tor Browser
  developers' signing key (pinned fingerprint in the repo), and records the SHA-256 in the manifest.
- Staged into `{app}\tor\`: `tor.exe` and its DLLs, `geoip`/`geoip6`, `lyrebird.exe` + `snowflake-client.exe`
  (for bridges), `pt_config.json`. About +20 MB to the installer, ~45 MB installed.
- Licences: tor is BSD 3-clause; each pluggable transport's licence goes into `THIRD_PARTY.md` and
  `{app}\tor\LICENSES\`. No Tor logo; wording "uses Tor" (Tor Project trademark guidelines).
- Each FX release ships the current stable Tor. The build fails if the signature doesn't verify.

### A2. The app runs its own Tor, only when needed
- New `tor_service.py`: starts `{app}\tor\tor.exe` **only when a route uses Tor**, stops it when none does and when
  the app exits (no Windows service, nothing left running).
- Own `DataDirectory` in `data\tor\` (keeps guard nodes and the consensus, so later starts take seconds), its own
  free SOCKS port on 127.0.0.1 (never 9050/9150, so it never clashes with Tor Browser), `ControlPort` with
  cookie auth on loopback only.
- Reads bootstrap progress over the control port (0-100 %) and shows it; `netlayer` treats the route as down
  until 100 % - the kill switch already blocks instead of going direct.
- **New identity** (control-port `NEWNYM`): a button, and automatically per Research run if you choose that.
- Per-chat circuit isolation: each chat uses its own SOCKS username (`IsolateSOCKSAuth`), so two chats' searches
  never share an exit.
- Crash handling: restarts once; if it fails again, the status says why (from tor's own log) and routed requests
  stay blocked.

### A3. Settings › Web search and network
- Route choices become: Direct · Windows' proxy · Proxy · **Tor (built in)** · Tor on this PC (the old "find
  9050/9150", kept for people who run Tor Browser).
- A one-switch shortcut on the same page: **"Search through Tor"** = Search part → Tor (built in). Models and
  everything else stay as they are unless you change them.
- Status line: Off / Connecting 63 % / Connected · exit country / Blocked (why). New identity button.
- **Bridges** (for networks that block Tor): Off / obfs4 (paste bridge lines) / Snowflake. Off by default.
- The network indicator in the top bar shows an onion-style "Tor" state while searches go through Tor
  (our own drawn icon, not Tor's logo).

### A4. Searching well through Tor
- Many engines block or CAPTCHA Tor exits. Through Tor, the DuckDuckGo provider uses **DuckDuckGo's official
  .onion address** (no exit node at all, rarely blocked); Brave/Tavily keys still work over Tor.
- Page reads through Tor: longer timeouts (Tor is slower), retry once on a new circuit when a site refuses an
  exit, and say plainly when a site blocks Tor ("this site refuses Tor; open it directly?" - one click, using
  the existing allow-direct-once).
- The assistant's own browser (browser.py) follows the Search route too, so a page it opens for a JS-heavy site
  also goes through Tor.
- `.onion` addresses: page reads of a `.onion` link **you** give work when the route is Tor; the assistant does
  not go searching for onion sites on its own.

### A5. Checks
- Tests: start/stop, port choice, bootstrap parsing, kill switch while bootstrapping, NEWNYM, isolation per chat,
  the DDG onion swap, no DNS leaks (the existing socket guard tests, run with the built-in route).
- Live: a search through Tor shows a Tor exit IP on check.torproject.org's API; first start time and later starts.

## Part B - Deep search (deeper into sites)

What Grok's DeepSearch does, from public write-ups (xAI hasn't documented the internals): it plans the
question, runs many searches, reads dozens of pages, **follows links into the sources it finds**, checks
claims across sources, shows a live trail of what it's reading, and then answers - in minutes, not a full
report. DeeperSearch spends longer on fewer, better sources.

### B1. A "Deep search" mode between a quick search and Research
- Composer Tools: **Deep search** (and `/deepsearch`). No plan card to approve - it starts at once and answers
  in the chat like a normal reply, with sources; Research stays for full reports.
- Two levels: **Deep** (~20-40 pages, a minute or two) and **Deeper** (fewer searches, more reading per site:
  follows links two levels into the best sources, prefers primary sources).
- Works in every appearance; in the Grok look it's labelled and drawn the way Grok shows it.

How the better open agents do it (WebThinker, Search-o1, OpenDeepSearch, and RAG retrieval research): **many
phrasings of the question, several kinds of source, a merge and re-rank, read only the passages that matter, find
the gap, search again**. Everyday answers to niche questions - a hardware bug, a game mod, a setting that fixes
something - are mostly in forums and Q&A threads, not articles, so forums are first-class sources here.

### B2. Asking better: query fan-out
- From the question the model writes 3-6 searches of different kinds, not one:
  - plain keywords, and a natural-language version;
  - the **exact phrase** in quotes (an error message, a model number, a quoted line);
  - the jargon an expert or a forum regular would use (the model writes a short "what the answer page would
    say" sketch and pulls its words out - the HyDE idea, used for wording only, never as a source);
  - operators where they help: `site:`, `intitle:`, `filetype:pdf`, a date range;
  - forum-shaped phrasings for experience questions: "anyone else", "fixed it", "[SOLVED]", "viewtopic",
    `inurl:forum`, `inurl:thread`;
  - the question in the language of the place it's about, when that differs.
- Each phrasing runs on the sources the router picks (B3), all at once, through the Search route.

### B3. More kinds of source, chosen per question
A **source router** picks sources by what the question is: opinions and experiences → forums and Q&A; an error
or bug → GitHub issues + Stack Exchange + forums; science → arXiv + Wikipedia; news → web with recency; a named
site → that site. Every source below was tested from this PC (28 Oct 2026):

| Source | How | Key? | Tested |
|---|---|---|---|
| Web search (existing) | Brave / Tavily / SearXNG / DuckDuckGo | optional | yes |
| **Hacker News** | Algolia HN Search API: stories and comments | no (10,000/h per IP) | 200 OK |
| **Stack Exchange** (Stack Overflow, Super User, Ask Ubuntu, 170+ sites) | API 2.3 search + answers, accepted/top answers | no (300/day per IP); optional free app key → 10,000/day | 200 OK |
| **Discourse forums** (thousands of project, game and community forums) | the forum's own `/search.json` and `/t/<id>.json` | no | 200 OK |
| **Lemmy** | `/api/v3/search` on a few big instances | no | 200 OK |
| **GitHub** issues and discussions | REST search (unauthenticated: 10 searches/min) | optional token | 200 OK |
| **Marginalia** | independent index with a **Forums** filter, small web, old pages | no (`public` key) | 200 OK |
| Wikipedia | MediaWiki search API | no | 200 OK |
| arXiv | export API | no | 200 OK |
| **Wayback Machine** | CDX API - reads a dead or changed page as it was | no | 200 OK |
| Reddit | official Data API with **your own free Reddit app** (Settings) | yes | keyless JSON and search return 403 |
| phpBB / XenForo / vBulletin / Invision forums | found through web search (B2's forum phrasings), then read as threads (B5) | no | per site; some refuse (XDA 403) |

- **Forum discovery:** any page that turns out to be a Discourse forum (it says so in its page) is remembered, and
  later questions about that topic can search it directly.
- **The rules:** an honest user agent naming the app, robots.txt respected, per-source pacing and the quotas
  above tracked, results cached. A site that refuses (403, a bot check) is marked "refused" in the trail and
  skipped - **no pretending to be a browser, no CAPTCHA solving**. Reddit works only with your own key; without
  one the trail says so.

### B4. Merging and ranking
- Results from every phrasing and source are merged with **reciprocal rank fusion** (k = 60), so a page several
  searches agree on rises; mirrors and duplicates fold together (sources.canonical, existing).
- The top ~40 are **re-ranked by the local model** in small batches from title + snippet + source type + date,
  against the question. Optional later: a small reranker model (bge-reranker GGUF on llama-server's rerank
  mode) as a download, for faster and steadier ranking.
- Existing boosts stay: primary sources up, content farms down, recent pages up for time-sensitive questions.

### B5. Reading, not skimming
- **Passages, not pages:** each page read is cut to the passages about the question and turned into short notes
  citing [n] (the Research ledger's notes, reused); the model never holds whole pages.
- **Threads as threads:** a forum or Q&A thread is read as question → accepted answer → top-voted answers → the
  original poster's own "fixed it" follow-up, with dates and versions kept, and **every page of the thread**
  (phpBB `&start=`, XenForo `/page-N`, Discourse JSON, vBulletin) - the fix is often on page 3.
- **Follow links:** from a page it read, the model can follow links on the same site (docs pages, "next", the
  cited study, the PDF, a thread linked as "see here") - two levels at most in Deeper, capped per site and per run.
- **Site search and sitemaps** when the question is about one site.
- PDFs through the existing reader; JS-heavy pages through the assistant's browser; a dead link through the
  Wayback Machine.

### B6. Weighing forum answers
- Every note is labelled by kind: **official** (docs, vendor, paper) · **Q&A** (with score / accepted) ·
  **forum experience** · **news** · **opinion**.
- Agreement is counted: "4 people in 3 threads report the same fix" counts for more than one confident post.
- Age matters: a 2019 answer about a 2026 driver is marked as old.
- The answer says which parts rest on forum reports, and what official sources say when they disagree.

### B7. The loop: find the gap, search again
- After each round the model lists what is still missing, what sources disagree on, and claims only one source
  makes - and writes the next round's searches for exactly those.
- Stops when two rounds in a row add little that is new (Research's saturation rule, reused) or the level's
  budget is spent: Deep ~3 rounds / 20-40 pages; Deeper ~5 rounds, fewer sources but whole threads and followed
  links.

### B8. The live trail
- While it works, the Thinking row shows each search, each source read (favicon, domain, and a small badge:
  forum, Q&A, paper, archive), threads opened, links followed, refusals - with a running count ("Read 27 pages
  on 14 sites, 6 forum threads"). It folds into "Searched 14 sites ▸" when the answer starts.

### B9. Privacy together
- Deep search and every source above follow the Search route: with "Search through Tor" on, forum APIs, page
  reads and followed links all go through Tor. (Stack Exchange's keyless quota is per IP, so over Tor it is
  shared with other Tor users - the optional free key avoids that.)
- Optional: a fresh Tor identity for each Deep search.

### B10. Checks
- Tests: query fan-out shapes, each source adapter (recorded responses), the RRF merge, thread pagination per
  forum platform, link-following caps and loops, robots.txt, quotas and pacing, refusals, trail events.
- **An evaluation set** of ~30 real questions, a third of them answerable mainly from forums (an obscure hardware
  fix, a game-mod conflict, a driver regression), run as normal search vs Deep vs Deeper: was the right answer
  found, how many sources, how long. The numbers go in the release notes, measured, not guessed.
- Live: the same questions over Tor.

## Open questions for you
- Installer size goes from ~92 MB to ~112 MB. OK, or would you rather Tor download on first use (smaller
  installer, one extra wait)? This plan bundles it, as you asked.
- Should "Search through Tor" be **on by default** for new installs, or off with a clear switch? (Plan: off -
  Tor is slower and some sites block it; the welcome's privacy step offers it.)
- Should cloud models (when used) also be allowed through Tor? Some providers block Tor exits. (Plan: allowed,
  off by default.)
- Reddit needs your own free Reddit app (client id + secret in Settings) - Reddit blocks keyless access. Worth
  adding the Settings field and guide, or leave Reddit out?
- The optional reranker model (~600 MB download): include in 1.4.4, or later?
